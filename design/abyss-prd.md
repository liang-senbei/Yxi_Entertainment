> 老板定的方向：**做成星穹铁道「忘却之庭 · 混沌回忆」那种深渊，大幅简化。**
> 本版把原作的每个要素逐条对照：留什么、怎么简化、砍什么。**第 3 节四项老板 2026-09-05 已全部按推荐拍板**（确定性结算 · 每半 0–2 位 + 旅人 · 半月 · 每 3 星曦光 ×2 + 36 星限定装扮自动发）。

## 1. 原作 → 我们（逐条对照）

| 星穹铁道 · 混沌回忆 | 我们的深渊 | 说明 |
|---|---|---|
| 12 关，难度递增 | **12 层**，难度递增 | 保留。层数、难度值放服务端 `abyss.json`，改数值不发版 |
| 每关分**上半场 / 下半场**，各派一队，**同一角色不能两边都上** | 每层分**上半 / 下半**，各派 **0–2 位**自己拥有的角色，同一层里一个角色只能出现在一半 | 保留原作最有味道的约束（把强角色放哪一半）。人数从 4 砍到 2：我们一共九位角色，且现在池子里只有云曦 |
| 回合制战斗，按**用了几轮**给 0–3 星 | **没有战斗，结算是确定性的**：每半算一个战力比 `r = 队伍战力 / 这半的难度`；上半过（r≥1）1 星、下半过 1 星、两半都余量充足（r≥1.3）再 1 星，共 0–3 星 | 这是最大的简化。没有随机数：不是赌，可以无限重排、随时重打，和原作「无次数限制」一致 |
| 敌人有**弱点属性**，克制才打得动 | 每半标 **2 个弱点性格**（取自九顶的性格词：空灵 / 纯真 / 深沉 / 悲悯 / 威严 / 炽烈 / 庄重 / 坚忍 / 冷酷 / 理性 / 高傲 / 包容 / 内敛…），带对应性格的角色战力 ×1.5 | 保留「看弱点配队」这个核心决策，用现有设定里的性格词代替属性，不新造体系 |
| 角色练度（等级 / 光锥 / 遗器 / 星魂） | **战力 = 基础值 + 命座**，命座 = 这个角色被重复抽到的次数（上限 6），`wish_grants` 里现成可数 | 砍掉全部养成材料，进度只来自抽卡 —— 抽卡与深渊互为目的 |
| 队伍不足时的**试用角色** | 每半自带一个**「旅人」**（玩家本人的底力单位，固定基础战力） | 现在多数玩家 0 或 1 个角色，没有这条深渊打不开门。旅人单独能打过前几层，往下必须有角色 |
| **记忆紊流**：每期一个全局增益 / 机制 | **本期「紊流」**：每期一条规则，如「第一期·浮云紊流：空灵·纯真 角色战力 ×1.5」 | 保留。是每期「重新配队」的理由。配置驱动 |
| 累计星数领奖（每星 60 星琼，36 星满） | **累计星数领奖**：每 3 星 → 曦光 ×2（共 24）；**36 星 → 本期限定装扮** | 保留结构，奖励换成我们的经济。余额不放，会员天数不放（同祈愿的理由） |

| 无次数限制、不耗体力 | **无次数限制、不花曦光** | 保留。确定性结算下重打 = 换队重排，本来就该免费 |

## 2. 玩家一期怎么玩（循环）

1. 半月初进深渊：看本期紊流、12 层每半的弱点与难度、上期结算。
2. 从第 1 层往下：每层给上半、下半各挑 0–2 位角色（同层不重复），页面**当场显示两半的战力比和预计星数**（确定性，不骗人）→ 点「挑战」→ 服务端结算、存下这层的最佳星数 → 过程动效（星轨 / 光爆，借实验室已有语言）→ 落定帧一行字：「第 4 层 · ★★☆」。
3. 累计星数每过一个 3 的倍数自动发曦光；36 星发限定装扮（自动发到账 + 站内信一封留底，不用手动领）。
4. 抽到新角色 / 命座升了 → 回来重打卡住的层。半月后重置，新紊流、新弱点，再来一遍。

## 3. 四项决定（老板 2026-09-05 已拍，全部按推荐）

| # | 决定 | 推荐 |
|---|---|---|
| ① 结算 | **确定性（无随机）**，无限重打不花曦光 —— 还是带一点随机 + 每天限次？ | **确定性**。不是赌博，符合「曦光不卖钱」的合规立场；原作也是练度决定一切 |
| ② 每半上阵 | **0–2 位 + 旅人底力**，同层不重复 | 现在角色少，2 位够；以后角色多了可以开到 3 |
| ③ 周期 | **半月** / 每月 | 半月 = 原作节奏 |
| ④ 奖励 | **每 3 星曦光 ×2（一期 24）+ 36 星限定装扮**，自动发 | 对照签到 ≈15 曦光 / 半月，深渊略高，但要真把塔打满才拿全 |

## 4. 数值起点（放 `abyss.json`，全部可调）

- 旅人基础战力 100；角色基础战力 120，每命座 +30（上限 6 → 300）；弱点命中 ×1.5；本期紊流 ×1.5。
- 层难度 `D(n)`（每半相同）：`100, 130, 170, 220, 280, 350, 430, 520, 620, 730, 850, 1000`。
  - 0 角色（两半都只有旅人 100）：过 1 层（r=1.0 一星）；这就是「先抽到云曦再说」。
  - 1 个云曦 0 命 + 弱点命中（120×1.5 = 180，加旅人 280）：那一半过到第 5 层，另一半只有旅人 → 合计约 6 星。
  - 云曦 6 命 + 紊流 + 弱点（300×1.5×1.5 = 675 + 100）：一半过到第 10 层；另一半仍靠旅人 → 想拿 36 星必须有第二、第三个角色 —— 给后续角色入池留出空间。
- 以上只是让老板看到「梯度」的样例，上线前按实际角色数再调。

## 5. 接口草案（cc-logto_yxi 定稿；命名避开 `tickets`）

```
GET  /api/abyss
     → {season:{id, name, startsAt, endsAt, turbulence:{text, trait, mult}},
        floors:[{n, up:{weak:[trait,trait], d}, down:{weak:[...], d}, myStars, myTeams:{up:[ids], down:[ids]}}],
        totalStars, claimed:[3,6,...], roster:[{id, dup, power}], travelerPower}
POST /api/abyss/floors/<n>   {up:[id...], down:[id...]}
     → {stars, up:{power, ratio}, down:{power, ratio}, totalStars, granted:[{kind, amount}]}   // 同层同角色不能重复 → 400
```
表：`abyss_progress(user_id, season, floor, stars, up_team, down_team, updated_at)`、`abyss_claims(user_id, season, threshold, granted_at)`。
星数发奖走现成 `tickets_move(reason='abyss')` / `wish_grants`；`abyss.json` 放赛季、紊流、弱点、难度、奖励。

## 6. 客户端（我做）

- 活动中心入口卡：本期塔名 · 我 N/36 星 · 距重置 N 天 · 红点 = 新一期开了还没打。
- 深渊页：顶部本期紊流一句话 + 星数进度条（3 星一格，格子亮 = 已发奖）；竖向 12 层，每层左右两半各显示弱点性格与我的最佳星数；点层进配队。
- 配队页：上半 / 下半两栏，横排我的角色卡（未拥有压暗不可选、另一半已用的压暗），旅人常驻；**实时显示两半战力比与预计星数**；「挑战」。
- 结果：过程动效借出货那套（星轨颜色 = 星数：3 金 / 2 紫 / 1 蓝 / 0 灰），落定帧干净一行。
- 减弱动效、深色皮肤、中英文、「取不到」≠「没有」，全部照 STYLE.md。

## 7. 验收

1. 0 角色的测试号能进深渊、旅人过第 1 层、拿到第一格 3 星奖励 → 再往下打不过且页面明说差多少战力。
2. 用测试号 `test-grant` 发曦光抽到云曦 → 回到深渊，配队页战力比变化、能多过几层；同层把云曦放两半被拒。
3. 改 `abyss.json` 一个难度值，客户端预计星数跟着变，不发版。
4. 星数跨过 3 的倍数曦光到账 + 站内信一封；36 星装扮到账、装扮页可选。
5. 期末重置：进度归零、装扮保留、新紊流生效；断网时页面说「取不到」。
