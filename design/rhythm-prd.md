## 1. 版权：他们的歌是怎么来的，我们能不能照抄这条路

### 1.1 Phigros / Orzmic 的曲子怎么来的

| | Phigros（鸽游 Pigeon Games） | Orzmic（BTworks） |
|---|---|---|
| 曲库 | 曲师**逐首供稿 / 逐首授权**：BMS 同人音乐比赛（THE BMS OF FIGHTERS）作品、SOUL NOTES 等音乐厂牌、与 Muse Dash 等音游**联动**拿到的曲子 | 一百余首**原创 + 已授权**曲目，国内外音乐制作人供稿 |
| 商业模式 | 公开自称**非商业**、爱好者团队「用爱发电」 | 公开自称**非商业运营**，免费、无 pay-to-win |

**两点必须看清**：

1. **他们不是"随便用歌"，而是一首一首谈下来的**。曲库里每一首背后都有一份曲师授权。
   看着"他们都是这么做的"，其实做的是**逐首授权**这件苦活，不是"音游可以用别人的歌"。
2. **他们靠"非商业"把授权成本压到极低**。曲师愿意无偿/象征性授权给一个不赚钱的爱好者项目，
   换成一个**有会员、有商城、有充值的商业 App**（就是我们），同一首歌的授权是另一个价钱、另一份合同，
   而且不少曲师会直接拒绝。**这条路我们不能照抄，只能照做（逐首谈），但要按商业授权谈。**

### 1.2 直接拿现成的歌会怎样（为什么不能"先上了再说"）

一首歌上有**两层权利**，缺一不可：

- **词曲著作权**（作者/版权公司）——把歌放进游戏、按它做谱面，属于复制 + 信息网络传播 + 同步使用；
- **录音制作者权**（唱片公司/制作人）——你用的那个**音频文件**本身是另一份权利。

从网易云 / QQ 音乐 / B 站扒音频放进 App，两层全侵。音游的侵权风险还**比普通游戏高**，因为：

- 歌是**完整播放**的，不是背景垫乐，属于"作品的核心使用"；
- 曲名、曲绘、曲师名都明晃晃写在选曲页上，**取证零成本**；
- 我们是收费 App，**赔偿按商业获利算**。

**结论：不能扒歌。** 这条没有"小规模应该没事"的余地。

### 1.3 我们能用的四条路（按推荐排序）

| 路子 | 成本 | 风险 | 说明 |
|---|---|---|---|
| **① 约稿买断 / 独家授权原创曲** ⭐推荐 | 一首几百到两千元，国内独立曲师，一两周交付 | **最低**：曲子是我们的，怎么改怎么用，还能进宣传物料 | 上线只需 3 首。曲子可以直接写成「云曦」的主题曲，跟角色绑定 |
| **② 真 CC0 曲库** ⭐推荐（起步用） | 0 | 低 | **必须是 CC0/公版**（放弃全部著作权、免署名、可商用）。注意 **Pixabay 音乐早就不是 CC0 了**，是它自家协议（能商用，但禁止"以音频本身作为独立商品"），音游里歌是主角，踩在这条边上，我不建议用 |
| ③ CC-BY 曲库（如 Kevin MacLeod 一类） | 0 | 低，但**必须在游戏内署名** | 选曲页和结算页要写清曲师和协议，少写一处就是违约 |
| ④ 商用曲库订阅（Epidemic Sound / Soundstripe 等） | 每首约 $100–600，或订阅制 | 中：**得逐条读协议** | 「royalty-free」≠「随便用」。**Artlist 明确规定游戏内使用要 Enterprise 套餐**，且禁止把素材当"独立内容"用；音游正好卡在这条上。选谁都要先确认协议里写明**允许在含内购的商业 App 的游戏内使用** |

### 1.3.1 我们自己合成的那三首：音色是怎么来的（cc-Yxi 2026-09-06 提的，值得写清楚）

**采样包 / SoundFont / 音源库本身是有许可证的** —— 有的禁止商用，有的要求署名，
用它们做出来的成品照样受限制。所以要说清我们的声音怎么来的：

`design/music/make_songs.py` **一个采样都没用**，全部是 numpy 现算的数学波形：
正弦 / 三角 / 锯齿 / 方波（`osc()`）、高斯白噪声当鼓的噪声成分（`np.random`）、
ADSR 包络、窗函数低通（`np.convolve`）、三抽头延时混响。
鼓、贝斯、旋律、铺底全部由这几样合成，**没有 SF2、没有音源库、没有第三方音频文件**。

所以三首曲子的**词曲和录音两层权利都在我们手上**：旋律和和声写在脚本里（是我们写的），
音频是脚本算出来的（不是任何人的录音）。生成脚本进仓库，将来要证明"这是我们的"，跑一遍就是证据。

### 1.4 无论走哪条，授权书里必须写到的（拿到就存档）

- 授权范围：**复制、发行、信息网络传播、以及为制作谱面所需的同步/改编**；
- 授权场景：**允许在含内购/会员的商业 App 内使用**（这句最关键，别只写"允许商用"）；
- 地域与期限：全球 / 不少于 5 年，或永久；
- 是否独家、能否用于宣传物料（选曲页封面、发版截图、宣传视频）；
- 曲师署名怎么写（游戏内固定位置）。

**授权书 PDF / 合同一律存到 `E:\资料`（老板定的规矩），文档里只写"见 E:\资料\音乐授权\"，真文件不进 git。**

### 1.5 另外两件也要早说的事

- **谱面必须自己做。** 谱面（notes 的时间与位置）是独立作品。扒 Phigros 的谱面文件同样侵权，
  哪怕曲子换成了我们自己的。视觉上也别抄它的判定线动画、UI 和角色。
  **玩法本身（下落式音符 + 判定线）不受著作权保护，放心做。**
- **版号（这条老板决定）**：国内政策口径是「免费且不开虚拟支付的游戏可以不要版号，一旦有虚拟支付要版号」。
  我们 App 有会员和曦光，音游本身不单独收费、也不消耗曦光的话更安全；
  这条对已经上线的祈愿 / 深渊同样成立，不是这个活动新引入的问题，但趁这次一起想清楚。

### 1.6 我的建议（一句话）

**上线三首：先用真 CC0 曲垫着把玩法跑起来，同时约稿 2–3 首原创曲，到货就换掉 CC0 那几首。**
一开始就别碰任何"能听出来是谁的歌"的东西。

## 2. 玩法（对照 Phigros / Orzmic，逐条决定留什么）

| Phigros / Orzmic | 我们 | 为什么 |
|---|---|---|
| 判定线**旋转、平移、多条**（Phigros 的招牌） | **一条固定判定线**，4 轨下落 | 会动的判定线是它的灵魂也是它的门槛：谱面难做、手机上难打、代码量翻几倍。我们要的是"活动里随手玩两把" |
| 音符类型：Tap / Drag / Hold / Flick | **Tap + Hold** 两种 | 两种就够撑起节奏感。Flick 在小屏上误判多 |
| 判定：Perfect / Good / Bad / Miss | **Perfect / Good / Miss** | 少一档少一堆边界 |
| 难度分级 EZ/HD/IN/AT | 每首 **两档：轻松 / 认真** | 三首曲子 × 两档 = 六张谱，够了 |
| 曲绘、剧情、角色收集 | **复用现有角色立绘**（云曦等九顶），不新画 | 不给美术加活 |
| 排行榜 | **不做** | 同深渊：昵称公开的问题没解决前不碰 |
| 体力 / 次数限制 | **不限次、不花曦光** | 同深渊。想打就打 |
| 结算：分数 + 准度 + 评级 | **分数 + 准度 + 评级（S/A/B/C）+ 最高连击** | 保留 |
| 自制谱 / 谱面编辑器 | **不做**（内部用脚本出谱） | 用户上传谱面 = 用户上传音频 = 又一摊版权 |

### 2.1 一局是什么样

1. 活动中心 → 「云曦节拍」→ 选曲（三首，每首两档难度，显示自己的最好成绩）；
2. 三秒倒计时 → 音符从上往下落到判定线，按拍点点/长按对应轨；
3. 判定 Perfect（±80ms）/ Good（±160ms）/ Miss，连击断了归零；
4. 结算页：分数、准度、评级、最高连击、这次拿到多少曦光。

### 2.2 分数与评级（确定性，跟深渊一个原则：不玩随机）

```
单音符满分 = 1_000_000 / 音符总数
Perfect = 满分       Good = 满分 × 0.65      Miss = 0
连击加成 = 最高连击 / 音符总数 × 100_000      # 封顶 10 万，鼓励别断
总分 = round(音符分之和 + 连击加成)           # 满分 110 万
准度 = (Perfect + 0.65 × Good) / 音符总数
评级：S ≥ 96% · A ≥ 90% · B ≥ 80% · C 其余
```

### 2.3 奖励（跟深渊同一套经济，别新造货币）

- 每首曲子**每档难度**首次达到 B → 曦光 ×1；首次达到 S → 曦光 ×2；
- 六张谱全部 S → 一款限定装扮（气泡或头像框，跟深渊的王棋彩框同一个发放机制）；
- **每档只发一次**，服务端用 `(user, chart, threshold)` 主键当闸门，重打不重复发（照抄深渊 `abyss_claims` 的做法）。

## 3. 技术要点（会踩的坑先写在这）

- **音画同步靠音频时钟，不靠 UI 时钟**：每帧从播放器取播放位置（AudioTrack 的 playback head / ExoPlayer 的 position），
  用它算音符该在哪。用 `System.nanoTime` 自己数拍，几十秒后必然漂。
- **必须有延迟校准**：不同手机的音频输出延迟差几十毫秒，不校准就是"明明按准了却 Good"。
  做一个校准页（跟着节拍点十下，取中位数偏移存本地）。这条属于 STYLE.md 的「不骗人」：
  判定不准还让玩家以为是自己手残，是最典型的骗人。
- **渲染**：Compose `Canvas` + `withFrameNanos`，只画进入可视窗口（约 1.5 秒）的音符。
- **谱面格式**：JSON `{song, difficulty, offset, notes:[{t, lane, type, dur}]}`，随包走，将来可下发。
- **降级**：系统开了「关闭动画」时不做花哨特效，但音符照常落（关掉的是装饰，不是玩法）。
- **静音 / 耳机拔出 / 来电**：暂停，别让它在后台空跑扣分。

## 4. 实现后的三处出入（照实记，别照着 PRD 想当然）

1. **分数由服务端算，不是客户端**（cc-logto_yxi 定的）：客户端只报判定计数
   `{perfect, good, miss, maxCombo, elapsedMs}`，服务端用同一套公式算分发奖 —— 客户端说「我拿了 S」不可信。
   契约 `logto_yxi/design/rhythm.md`。
2. **分母是 units 不是音符数**：长按算两个判定（头 + 尾），`units = notes + holds`。
   ⚠️ **以后跑 `make_songs.py` 改了谱面，units 会变，必须先告诉 cc-logto_yxi**，
   否则服务端配置对不上，所有提交都会被判 `bad_counts`。
3. **评级显示读 `bestRating`（历史最佳评级），分数读 `best.score`（最高分那一局）** —— 两者会背离：
   分数含连击加成、评级只看准度，104.4 万/A 会盖掉 102.5 万/S。混用会把已经拿到手的 S 显示成 A。
4. **校准没做成单独的页**：改成结算页发现这局平均偏差 ≥30ms 就直说「你平均按早了 N 毫秒」并给一个校准按钮 ——
   同样解决问题，还少一个页面。

分工：玩法 / 渲染 / 判定 / 谱面 / 曲子 = 我；服务端 = cc-logto_yxi。
曲子将来要换真人做的，走 1.3 节 ① 约稿买断，我可以把需求写成一页给曲师。

## 4.5 打击感（老板 2026-09-06 第二轮：「特效符合我们 App 的 UI/UX 风格，音效点击音效动效震动都要做，先参考竞品」）

**竞品的共识**：打击感的主体是**声音和震动**，画面只是补。Muse Dash 是「星星炸开 + 轻微震动」，
Phigros 是金属感的「嗒」，Cytus 偏电子。所以先把声音和震动做对，再谈特效。

- **打击音效** `res/raw/yx_tap.ogg`（55ms，`design/music/make_sfx.py` 合成，无采样包）：
  木质的体 + 一点金属泛音，连打三十下不烦。SoundPool 播（一局响一两百次，MediaPlayer 不适合），
  一个样本靠音量和速率分「完美 / 不错」。**漏了不响**。
- **震动**：`performHapticFeedback`（不申请 VIBRATE 权限 → 自动尊重系统触感开关）。
  完美 CONTEXT_CLICK、不错 CLOCK_TICK、**漏了不震**（漏了再震是惩罚不是反馈）。
- **两个开关**在选曲页，各自记住。
- **画面按 `design/STYLE.md` 的玻璃语言做**（不是照抄竞品的粒子爆炸，那不是我们的调性）：
  轨道往判定线渐亮 · 手指按下先亮一下（反馈"你按了"）· 判定线三层（底光 + 线 + 亮芯）·
  命中扩散一圈光环 + 一道上冲光柱（完美铜色、不错琥珀）· 漏了一小片暗红 ·
  音符是带顶部高光的圆角条 · 连击弹一下 · 评级字浮出来。
- **关了系统动效**：以上装饰全停，**音符照落** —— 音符是玩法不是装饰。

⚠️ 音效和震动**在模拟器上验不了**（`-no-audio`、没有马达），手感要真机才算数。

## 4.6 横版 + 观感重做（老板 2026-09-06 第三轮：发了 Phigros 实机视频，「逐帧研究，能复刻的都复刻，但改成横版」）

**边界**（跟版权那节同一条）：**玩法和视觉语言可以学，素材和谱面数据不能拿**。
他们的曲绘 / 字体 / logo / 角色 / 谱面文件一概不碰；**判定线的运动曲线属于谱面数据**，

从视频里量到的、已经落地的：

  实测谱重心 4511Hz / 6kHz 以上 30%（`make_sfx.py`），跟量到的同一个量级。

  几个小方块朝上散开减速，共约 380ms（`hitBurst`）。配色曲线是我们的（暖铜 / 琥珀）。
- **横版**：进游戏转横屏、离开还原（依赖 MainActivity 的 configChanges，注释里钉住了）；

- **HUD 横版布局**：退出左上 · 连击正中 · 分数右上（7 位补零）· 曲名和难度在下两角 · 进度条在顶端。

**下一轮（还没做）**：判定线的移动 / 旋转 / 显隐（给谱面加 line-events）、结算页照横版重做。

⚠️ **不加 Drag / Flick 音符**（cc-logto_yxi 2026-09-06 提醒后确认）：老板这一轮要的是

## 4.7 v2 规格（老板 2026-09-06 亲自给的一版完整规格，**覆盖 §2 里「只做 Tap + Hold」那条**）

### 四种音块

| 名字 | 怎么打 | 颜色 | 形状（**颜色之外还要靠形状分得出**：色盲、强光） | 判定数 |
|---|---|---|---|---|
| tick | 点一下 | 淡橙 | 光胶囊 | 1 |
| slide | 长按 + 滑 | 浅蓝 | 胶囊 + 尾轨 | **2**（头 + 尾） |
| trace | 拖动换位 | 樱粉 | 胶囊 + 抓握纹 + 指向目标轨的箭头 | 1 |
| swipe | 落下时左滑或右滑 | 浅绿 | 胶囊 + 左/右尖角 | 1 |

⚠️ **判定数变了就要先通知 cc-logto_yxi**：`units = 音符数 + slide 数`，服务端拿它算分、校验计数、卡 maxCombo 上限。
顺序是**先给他新的 charts-meta.json → 他更新 rhythm.json → 客户端才发版**，反了线上提交全被判 `bad_counts`。

### 校准线倾斜（trace / swipe 造成）

**倾斜是一个衰减中的偏移量，不是状态。** 每次 trace/swipe 成功校准，把倾斜朝那一次的方向拉一把
（`tilt = tilt × 0.55 + dir × 幅度`，封顶 ±6°），之后每帧朝 0 衰减，约 0.4 秒回正。**绝不累加**；
方向相反的两个块同时中，自然互相抵消。它跟谱面自己的线事件是**叠加**关系（编曲写的 + 玩家造成的，相加再封顶）。

⚠️ **倾斜不影响判定。** 判定只看**音符时刻 + 音频时钟**。角度只进两处：画面，以及把手指坐标反变换回线坐标系 ——
两处用**同一个角度**，所以"看到的轨"和"点中的轨"永远一致。倾斜改的是"轨画在哪、点哪儿算它"，
不改"什么时候算准"。（跟手感面板里的「音符下落」不完全同源：那个是纯画面，判定路径一次都不引用；
倾斜是画面 + 命中区一起转。两者都不碰时间判定。）

### 校准瞬间

一条**垂直于校准线**的竖线，带 ±10° 随机偏转，然后淡出。

### 命中特效

四种块各不相同（圆形扩散等，自己发挥），但都建立在已有的分层爆点上。

### 背景随分数变色

分数越高越"火热"。⚠️ **参照物在我们自己 App 里**：对话输入框的渐变（`GlassPill` 的色相流动）
和 AI 思考时那层光晕（`ThinkingGlow`）。不是去外面找参考。

### 连击倍率（老板 2026-09-06 定稿）

`×8 Great 1.2` → `×15 Excellent 1.5` → `×30 Amazing 2.0`，**断连击直接掉回 1.0**。
Perfect 留给单音符的完美判定，不当连击档位用。

⚠️ **门槛 / 倍率 / 词全从服务端下发**（`rules.comboTiers` = `[{at, mult, label}]`），客户端一个不写死 ——
老板要调，服务端改一行配置就生效，不用发版。没下发时**完全等于没有倍率**。

⚠️ **分数仍然是服务端算的**：倍率取决于"每一下是在第几连打出来的"，聚合计数推不出来。
所以上报改成带**判定序列** `hits`（每判定一个字符 P/G/M，按判定发生的时间顺序，长度 == units），
服务端拿原始事实重算连击、倍率、分数、准度、评级。聚合计数照旧一起报，服务端两边逐项对，
不一致就 `bad_counts`。
> 这是 cc-logto_yxi 的方案，比我最初提的 `tierHits`（分档命中数）好：tierHits 是"客户端算完的结论"，
> 要加一堆交叉校验防撒谎；序列是**原始事实**，校验只剩长度一条，而且以后再改计分规则协议都不用动。

⚠️ **切到倍率那天要清 `rhythm_best`**（满分 110 万 → 约 210 万，尺度变了），`rhythm_claims` 一条不动。
2026-09-06 已执行：清 6 条最好成绩、领奖记录一条没动。选曲页有一句说明，玩家才知道成绩为什么重算。

### 评价词

参考图 `Yxi/design/judge-words-ref.png` 是**老板自己 AI 生成的**（cc-Yxi 核实），不是扒的音游，可以照着做。
做法：粗斜体 + 亮色填充 + 深描边 + 外发光 + 斜切色块 + 细斜线 + 四角星。
⚠️ 图是浅底、我们是**固定深色舞台**，配色要反过来配（白填充黑描边搬过去会糊）。
实现不带任何字形文件：系统字最重字重 + 斜体，装饰全是画出来的几何体。

### 判定窗口（老板 2026-09-06 放宽 50%）

完美 ±120ms / 不错 ±240ms。这是改**默认难度**，**不是**把窗口开放给用户调 ——
手感面板里没有这一项，放开了等于自己给自己发 S。
旧成绩不用清：公式、分母、评级门槛都没动，尺度没变，只是当时更难拿（跟"units 变了"和"加倍率"是两回事）。
